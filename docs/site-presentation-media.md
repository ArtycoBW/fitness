# Видеопревью личного кабинета

Файлы `apps/web/public/media/account-preview-loop.mp4` и `account-preview.webp` используются в секции личного кабинета на главной странице.

Видео снято с работающего интерфейса приложения в Chromium: обзор кабинета, открытие расписания, выбор абонемента и возврат в кабинет. Это запись браузера с настоящими переходами, анимациями и модальными окнами. Кадры интерфейса не сгенерированы и не собраны из неподвижных изображений.

## Параметры медиа

| Параметр           | Значение                 |
| ------------------ | ------------------------ |
| Размер кадра       | 2560 × 1776 пикселей     |
| Частота кадров     | 30 кадров/с              |
| Длительность цикла | 22,23 секунды            |
| Контейнер / кодек  | MP4 / H.264              |
| Звук               | Отсутствует              |
| Постер             | WebP, первый кадр записи |

Чёткость получена при растеризации интерфейса самим браузером. Физический viewport составляет 2560 × 1776 пикселей; масштаб CSS 2 соответствует композиции 1280 × 888 CSS-пикселей. Размеры элементов, зависящие от высоты viewport, приведены к размеру этой композиции только в окружении записи. Низкое разрешение не увеличивается программным масштабированием после съёмки.

Исходные кадры захвачены через Chromium DevTools Protocol в PNG и закодированы в H.264. Размер кадра и частота проверены через `ffprobe`; обзор, расписание и выбор абонемента дополнительно проверены на отдельных кадрах. Постер изготовлен из первого кадра той же записи.

## Данные и границы записи

Съёмка выполняется в изолированном окружении с подготовленными вымышленными данными. Секреты авторизации, токены, реальные платёжные реквизиты и учётные данные пользователей не входят в медиа или документацию. Пароли и банковские данные в кадре не раскрываются.

Оплата в этой версии приложения обрабатывается внутренним имитационным адаптером на сервере. Превью не подтверждает подключение к банковскому эквайрингу или реальные денежные операции.

Сценарии записи, временные кадры и настройки окружения находятся вне проектных исходников. При обновлении интерфейса следует переснять превью в исходном разрешении, проверить его первый и последний кадры, затем обновить MP4 и WebP вместе. Плеер сохраняет пропорции 160:111, предоставляет паузу и учитывает предпочтение уменьшенного движения.
